# 让口语成为可用的 Prompt

[返回首页](../README.md)

下面是期望的整理方向，用来理解产品行为，并非逐条模型实测或确定输出。相同内容可能因模型配置得到不同措辞。

## 1. 开发需求：保留范围与停止条件

**输入**

> 嗯，那个登录页在手机上有点问题，按钮好像看不全。你先看一下原因，先不要改数据库，也别部署。

**期望草稿**

> 请检查登录页在手机上按钮显示不完整的问题，先分析原因。暂时不要修改数据库，也不要部署。

“好像”表达问题尚待确认；润色不能自行断言是 CSS、接口或数据库导致的，也不能把“分析”变成“实施”。

## 2. 产品设计：归纳重复，不扩充功能

**输入**

> 我想做那个录音时的界面，就简单一点，浅色的，像音波一样，不要很大的框，就是不要边框。

**期望草稿**

> 请设计简洁的录音界面，使用浅色音波动效，不要大面积容器或边框。

可以合并重复的风格要求，不应加入账户系统、付费订阅或新的交互流程。

## 3. 英文输入：保持英文

**Input**

> Um, can you check the checkout button on mobile? I think it gets cut off. Just investigate for now, don't change the payment flow.

**Expected draft**

> Please investigate whether the checkout button is cut off on mobile. Do not change the payment flow yet.

不需要把英文翻译成中文，也不需要在每次录音前切换语言。

## 4. 数字、路径和否定限制不能丢

**输入**

> 帮我看 src/auth.ts，超时要保持 30 秒，不要变成 60 秒，也不要重命名 loginUser。

**期望草稿**

> 请检查 src/auth.ts。保持超时为 30 秒，不要改成 60 秒，也不要重命名 loginUser。

这里的文件路径、函数名、两个数字与否定限制都必须保留。项目有保真检查与原文回退，但不应把它理解为对所有改写错误的完全检测。

## 选择整理强度

- `raw`：保留转录原文，跳过 AI 编辑。
- `clean`：清理口头禅、重复和明显的表达问题。
- `agent`：把原话中的目标、背景、顺序与限制整理清楚，不增加任务范围。

## 在 MiniMax Code 里体验

选中 `@Voice Prompt`，输入或说出上面的示例后发送。插件应返回可复用的草稿，不执行草稿里的任务。想让语音先润色、再出现在发送框中，则在桌面端打开自动润色；这一步由本地应用完成。

体验时对照原话检查：是否保留否定限制、有没有新增要求、产品名有没有被误改、数字是否一致。确认后再把草稿发送给工作 Agent。
