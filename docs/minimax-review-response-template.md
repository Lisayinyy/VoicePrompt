# Voice Prompt · MiniMax Code 审核回复模板

日期：2026-09-12  
状态：审核沟通模板；用于 MiniMax / Mcode 插件审核期间回复常见问题。此文件不是官方审核结果，也不表示插件已经发布。

## 1. 产品范围说明

Voice Prompt 首版提交范围是 **本地 MCP + Skill + macOS 桌面伴侣应用**。

- MiniMax Code 插件层：提供 `@Voice Prompt` 的状态检查、首次安装引导、给定文本整理、与桌面工作流连接说明。
- macOS 桌面应用：负责全局快捷键、录音、本地 ASR、实时预览、可选 AI 润色和输入框填入。
- 当前 0.7.1 候选包：不宣称已经是 MiniMax 托管的远程 Streamable HTTP MCP Connector。

建议回复：

```text
Voice Prompt 当前提交的是本地 MCP + Skill + macOS 桌面伴侣应用组合。MiniMax Code 插件用于引导和连接桌面工作流；录音、实时预览和输入框填入由用户本机的 macOS 应用完成。我们没有把当前 REST API 宣称为已通过联调的远程 MCP Connector。
```

## 2. 权限问题

如果审核问为什么需要麦克风、辅助功能、网络或本地存储：

```text
麦克风仅在用户主动按快捷键开始录音后使用。辅助功能用于把用户确认前的整理结果填入当前聚焦输入框。网络用于下载本地模型文件，以及在用户启用 AI 润色时调用配置的模型服务。本地存储用于保存应用、模型文件和非敏感运行状态。插件导入不会自动授予这些系统权限，用户需要在 macOS 中确认。
```

## 3. 数据处理问题

如果审核问是否上传音频或保存用户数据：

```text
首版设计中，录音由桌面应用在用户本机采集。本地 ASR 在用户 Mac 上运行。开启 AI 润色时，发送的是转写后的文本和可选术语，不会因为文字润色自动上传原始录音。用户会在发送前看到填入的最终文本，并自行确认是否发送。
```

## 4. 安装依赖问题

如果审核问插件导入后为什么不能直接完成全部功能：

```text
MiniMax 插件负责 MCP 工具和 Skill 引导；全局快捷键、系统录音、输入框注入属于 macOS 桌面应用能力，需要用户安装桌面应用并授权麦克风和辅助功能。我们在插件说明、安装说明和数据权限说明中明确区分了插件能力和桌面应用能力。
```

## 5. 云端润色和费用问题

如果审核问是否使用发布者统一额度、是否复用 MiniMax Code 用户订阅：

```text
当前 0.7.1 上架候选包不包含发布者统一付费的共享云端润色额度，也不会读取或提取 MiniMax Code 用户订阅凭据。后续如果提供共享云端润色，会通过正式 HTTPS API、客户令牌、额度限制和隐私说明单独验证后再提交更新。
```

## 6. 远程 MCP Connector 问题

如果审核要求远程 MCP 或 App Connector：

```text
当前包按本地 MCP + Skill 路线提交。若 MiniMax 要求远程 MCP Connector，我们会单独实现 Streamable HTTP MCP endpoint，完成 initialize、tools/list、tools/call、鉴权、限流、错误码和区域网络联调后，再提交对应版本。不会把现有 /voice/prepare REST 接口直接描述成已通过联调的远程 MCP。
```

## 7. 测试和验证问题

如果审核问当前验证范围：

```text
提交前自动检查包括 ZIP 校验、自动隔离 clean preflight、提交材料审计、公开链接检查和源码测试。该检查证明候选包结构、公开材料和本地测试通过；它不证明 MiniMax marketplace 已审核通过、已发布、物理新机授权测试完成或新用户一定能安装成功。正式审核状态以 MiniMax 返回为准。
```

## 9. 不要这样回复

- 不要写“已经上架”或“已经发布”，除非 MiniMax Code 市场真实可见。
- 不要说插件导入后会自动安装桌面应用、模型或系统权限。
- 不要说当前 REST API 已经是 MiniMax 托管的远程 MCP Connector。
- 不要承诺无限免费云端润色额度。
- 不要在审核回复里粘贴真实 API Key、客户令牌、私有邮箱以外的敏感信息。
