## 可复现构建

在仓库根运行 `python3 scripts/pack-minimax.py` 或 `npm run pack:minimax`。构建不读取个人配置，不安装桌面应用，不调用模型。需要 Python 3 标准库；测试还需要 Node 22+。

输出在 `dist/minimax/`：

- `voice-prompt-minimax-0.7.1.zip`：供平台评估/投稿的专用包
- 同名 `.zip.sha256`：完整性校验
- `voice-prompt-minimax-0.7.1.validation.json`：本地预检报告，含文件数、体积与哈希

校验已有 ZIP：`python3 scripts/pack-minimax.py --validate dist/minimax/voice-prompt-minimax-0.7.1.zip`

**本次选择 ZIP 作为投稿来源。** `minimax/` 是模板目录，缺少构建时加入的运行依赖，不可把它当成完整 GitHub Plugin 子目录直接提交。仓库根原有 OMP/通用插件格式也不是这个 MiniMax V1 ZIP。需要 GitHub 子目录投稿时，应发布完整解包内容到固定 commit，而不是提交模板。

插件包装版本 0.7.1；现有桌面依赖固定 v0.7.0-beta.3。这次没有声称桌面二进制已更新。后续包内容变更继续升版本，不复用已提交版本。

## 这份包实际能做什么

配合现有桌面应用检查安装、查看状态与模型、整理明确给定的文字、转录指定本地 WAV。全局录音、波形、实时预览、自动润色开关和填入由桌面应用负责。用户确认后发送。

未安装桌面时，Skill 提供完整 Agent 辅助安装路径，固定下载来源与校验值。插件 ZIP 不包含桌面二进制、Qwen 权重、Python/Node 二进制、生命周期安装钩子或任何账号凭据。没有运行时会准确提示先使用 Skill 安装，不会在导入时静默下载。

首版候选仍使用客户已有润色服务或本人 OMP 配置；不能对同事宣传“自动使用发布者无限额度”。@ 后由宿主 Agent 整理、快捷键结束后桌面自动润色是不同入口。

- 无运行时有可行动的 Skill 安装提示；拒绝携带 hooks、路径穿越、重复 JSON key、缺失运行文件的归档
- 全套源码测试 46 项通过，包括后端鉴权/额度、保真润色、取消、OMP 编辑区保护
- 固定 v0.7.0-beta.3 发布页及 SHA256SUMS 在本次可读取；这不等于已在第二台电脑下载、授权与录音成功

## 本机安装与候选包一致性

本机安装器现在直接构建、校验并解包相同 MiniMax 投稿 ZIP，不再生成另一份 manifest 或从宿主素材池取图标。安装前保留旧插件备份；失败时回退。隔离测试逐文件比较安装目录与 ZIP，确认 package.json、MCP 版本、Skill 及图标一致。

已在发布者的 MiniMax 本地插件目录安装 0.7.1，产物 SHA-256 与投稿 ZIP 一致。通过新 launcher 完成真实 MCP 调用及一次合成中文润色，保留数字 2.0 和数据库限制。第一次真实校验未通过（当时验证器没有区分回退与约束丢失）；随后直接服务和新 MCP 调用成功。因此本次只证明链路可用，不能据此声称润色稳定性或新设备体验已达发布标准。验证器现已在失败时报告回退状态及两项约束是否保留，不打印凭据。

本机没有可用 Developer ID 代码签名身份；候选仍依赖已明确标注的 ad-hoc 桌面内测包，不宣称完成公证。

## 正式提交前的关口

1. **平台分类**：让 MiniMax 确认配套桌面应用、本地身份与云端润色的分类是否接受此本地 MCP 方案；如要求 App/Connector，应先实现远程 MCP、联调并取得真实 provider
2. **公开共享服务**：确定正式域名、运营/备案主体；完成 HTTPS、每用户授权和配额，确认上游套餐允许该服务用途。详见 [HTTPS 方案](https-and-mcp-release-plan.md)
3. **首次体验**：已签名、公证的桌面发布与受支持的新 Mac 完整测试；没有开发者 SSH、OMP 登录和私有配置时也要验证实际录音、润色、填入
4. **投稿身份**：提交账号、邮箱、CN 新建/更新、支持联系人及需提供的隐私政策与使用说明

平台可先评估此候选包与 [接入材料草案](minimax-submission-readiness.md)，尚未发送。只有在服务/依赖边界获确认后，才把候选包作为正式投稿提交并记录 submission_id。平台发布和市场实际可见性分别核验。
